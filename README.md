# 自动息屏 (Auto Screen Off)

一个 Android 应用：**刷视频睡着时自动关闭视频 App 并锁定屏幕**，停止播放，省电、省流量。

## 下载安装

最新正式签名版：**[Releases · SXHLY/Auto-screen-off](https://github.com/SXHLY/Auto-screen-off/releases/latest)**（`AutoScreenOff-v1.0.32-release.apk`，1.7 MB）
- 安装：手机开启"允许安装未知来源应用"后，将 APK 传到手机点击安装；或用数据线连接后执行
  `adb install AutoScreenOff-v1.0.32-release.apk`

## 解决的问题

刷短视频/看视频睡着后，手机还在后台继续播放，白白消耗电池和流量。
本应用通过感知「你是否还在操作」，在确认你已睡着后**先结束视频应用、再锁屏**。

## 核心链路

```
无障碍事件（前台包名 / 触摸滑动）+ 加速度传感器（运动模式分析）
        │
        ▼
条件评估（ScreenOffController，每 15s 兜底一次）
  总开关 ∧ 未暂停 ∧ 屏幕亮 ∧ 解锁>1min ∧ 冷却>90s
  ∧ 时间段内 ∧ 前台是目标应用 ∧ 无操作超时 ∧ 无清醒运动信号
        │ 全部满足
        ▼
息屏前悬浮窗倒计时（默认 10s，可配 5~30s，碰屏或持续运动 1.5s 取消）
        │ 无人取消
        ▼
AppTerminator 关闭链路：
  ① GLOBAL_ACTION_HOME 退回桌面（停止前台播放）
  ② DevicePolicyManager.lockNow() 立即锁屏
  ③ 延迟 800ms killBackgroundProcesses(pkg) 结束后台进程
  ④ （可选，默认关，仅设备所有者可用）setPackagesSuspended() 强力冻结，解锁自动恢复
```

## 功能与感知来源

| 感知/执行 | 实现方式 |
|---|---|
| 前台应用包名 | 无障碍服务 `TYPE_WINDOW_STATE_CHANGED` 事件（事件驱动、零轮询） |
| 用户滑动/触摸 | 无障碍服务 `TYPE_VIEW_SCROLLED` / `TYPE_TOUCH_INTERACTION_START`；视频自动刷新的进度条、弹幕是 `TYPE_WINDOW_CONTENT_CHANGED`，**不算**操作 |
| 运动状态 | 加速度计（`SENSOR_DELAY_UI` 注册 + 400ms 软件节流），三档行为模式分析（见下文） |
| 屏幕亮/灭/解锁 | `ACTION_SCREEN_ON / SCREEN_OFF / USER_PRESENT` 广播 |
| 息屏 | 设备管理员 `DevicePolicyManager.lockNow()` |
| 关闭视频 App | 回桌面（无障碍全局动作）→ 锁屏 → `killBackgroundProcesses()` 杀后台；可选 `setPackagesSuspended()` 冻结 |
| 息屏前提醒宽限期 | 系统悬浮窗倒计时（无障碍悬浮窗为主、普通悬浮窗为降级），全屏覆盖、触摸任意处取消 |
| 常驻保活 | `specialUse` 前台服务 + 常驻通知（带"暂停 30 分钟"快捷按钮） |
| 手动暂停 | 设置页（15min~8h）/ 通知按钮（30min）/ 快捷设置磁贴 |
| 开机自启 | `BOOT_COMPLETED` 接收器重启保活链路 |

## 触发条件（全部满足才执行关闭+锁屏）

1. 总开关开启，且未被手动暂停
2. 处于设定时间段内（如启用，支持跨午夜 23:00–07:00）
3. 前台应用在目标列表中（支持应用专属时长，如 B 站长视频 60 分钟、抖音 5 分钟）
4. 超过该应用的无操作时长没有任何滑动/触摸
5. （可选）运动检测：明显运动（拿起/走动/翻身）阻止触发；**规律呼吸级微动不阻止**（睡着握着手机/放胸口），但要求 1.5 倍无操作时间
6. 屏幕亮着，解锁超过 1 分钟（宽限），距上次触发超过 90 秒（冷却）
7. 确认倒计时结束无人取消（如开启弹窗确认；取消后 10 分钟内不再打扰）

## 设计决策

### 目标 Android 版本与权限矩阵

| 项目 | 取值 | 说明 |
|---|---|---|
| minSdk | 26（Android 8.0） | `setPackagesSuspended`（API 24）、前台服务（API 26）均可用 |
| targetSdk / compileSdk | 34（Android 14） | Android 14 强制前台服务类型声明；在 Android 15 设备上运行正常（如需 targetSdk 35 以获得 15 的完整行为适配可后续升级） |

| 权限/能力 | 类型 | 用途 |
|---|---|---|
| `BIND_ACCESSIBILITY_SERVICE` | 特殊权限（用户手动开启） | 前台包名、滑动/触摸事件、全局回桌面动作；**不读取屏幕内容**（`canRetrieveWindowContent=false`） |
| `BIND_DEVICE_ADMIN` | 特殊权限（用户手动激活） | `lockNow()` 锁屏；`setPackagesSuspended()` 冻结应用**仅设备所有者可用**（普通手机不可获取，应用会自动禁用该模式） |
| `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE` | 安装时授予（API 34 需显式声明 specialUse 类型与用途属性） | 常驻监测服务 |
| `KILL_BACKGROUND_PROCESSES` | 普通权限，安装即授予 | 锁屏后结束目标应用**后台**进程 |
| `POST_NOTIFICATIONS` | 运行时权限（API 33+） | 状态通知、无障碍被关闭告警 |
| `SYSTEM_ALERT_WINDOW` | 特殊权限（可选） | 息屏确认弹窗的**降级**通道（主通道为无障碍悬浮窗，无需该权限） |
| `RECEIVE_BOOT_COMPLETED` | 普通权限 | 开机重启保活链路 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 普通权限 | 引导加入电池优化白名单 |
| `ACCESS_FINE_LOCATION` + `FOREGROUND_SERVICE_LOCATION` | 运行时权限（可选，驾驶检测默认关） | 只读最后已知定位的**速度**判断行驶；不主动请求定位、不上传位置 |
| `ACCESS_NETWORK_STATE` | 普通权限 | 监听 WiFi↔蜂窝切换（GPS 不可用时的行驶降级信号）；不读取网络内容 |
| `INTERNET` + `REQUEST_INSTALL_PACKAGES` | 普通 + 特殊 | **仅**仓库更新检查/下载/升级确认使用；平时零联网，不上传任何数据 |
| 加速度计 | 无需权限 | 运动检测（`BODY_SENSORS` 仅限心率等敏感传感器，加速度计不涉及） |

> **关于 UsageStatsManager（使用情况访问）**：它可以轮询 `queryUsageStats()` 获取前台应用，但需用户单独授权 `PACKAGE_USAGE_STATS`，统计有最小间隔延迟，且轮询耗电。本应用选择无障碍事件作为主通道（事件驱动、零轮询、顺带拿到触摸事件），语义与实时性都更好。UsageStats 可作为备用校验手段保留在方案里，未启用。

### 静止判定算法（MotionMonitor）

- **传感器**：`TYPE_ACCELEROMETER`（含重力），`SENSOR_DELAY_UI` 注册，软件节流 **400ms/采样**（≈2.5Hz，息屏场景足够，耗电可忽略）
- **特征**：合加速度幅值经一阶低通滤波（α=0.15）得到平稳基准，计算抖动 `jitter = |幅值 - 基准|` 与重力偏差 `|幅值 - 9.8|`
- **三档判定**：

| 档位 | 条件 | 语义 |
|---|---|---|
| 大幅运动 BURST | jitter > 0.9 m/s² 或重力偏差 > 1.2 m/s² | 拿起/走动/翻身 → 清醒信号，重置无运动计时 |
| 随机微动 MICRO | 0.10 < jitter < 0.90 | 清醒小动作，时间戳入队做规律性分析 |
| 静止 | jitter ≤ 0.10 | 传感器噪声级 |

- **呼吸识别**：90s 窗口内，微动间隔落在 2~8s（约 7.5~30 次/分）且至少 4 个、间隔变异系数 CV ≤ 0.35 → 判定为「规律呼吸级微动」（入睡特征）→ 不阻止触发，仅要求 1.5 倍无操作时长，解决"睡着握着手机永不锁"与"醒着看长视频被误锁"两端问题

### 关闭视频 App 的实现路径与系统限制

**系统限制（必须了解）**：第三方应用**无法强制结束其他应用的前台进程**（`forceStopPackage` 是系统签名权限）。可行路径只能是"先让它退到后台，再结束后台进程"：

1. `performGlobalAction(GLOBAL_ACTION_HOME)` —— 无障碍服务把目标应用退回桌面，前台播放立即停止
2. `lockNow()` 锁屏 —— 应用随屏幕熄灭进入后台
3. 延迟 800ms 后 `ActivityManager.killBackgroundProcesses(pkg)` —— 结束后台进程，停止后台音频/预加载/长连接（只能杀后台进程，顺序不可调换）
4. （可选，默认关）`DevicePolicyManager.setPackagesSuspended()` —— 设备所有者把应用置为"已暂停"，完全冻结全部组件，连启动器都打不开；用户**解锁屏幕时自动恢复**（`ACTION_USER_PRESENT` 监听），避免醒来后困惑。此能力仅设备/配置文件所有者可调用，普通手机上应用自动禁用该模式

### 息屏方案与降级处理

| 优先级 | 方案 | 条件 | 降级 |
|---|---|---|---|
| 主 | `DevicePolicyManager.lockNow()` | 设备管理员已激活 | — |
| 降级 1 | 只关闭应用不回锁 | 未激活设备管理员 | 杀后台进程停止播放，屏幕由系统超时自然熄灭 |
| 降级 2 | 确认弹窗缺失 | 无障碍与普通悬浮窗都不可用 | 跳过倒计时直接执行关闭链路 |
| 降级 3 | 降低打扰 | 用户取消倒计时 | 10 分钟冷却期不重复弹窗 |

（无 root/系统签名前提下，普通应用无法直接熄灭屏幕或修改系统亮度——`PowerManager.goToSleep()` 是隐藏 API，亮度调节需要修改系统设置权限且仅作用于本应用窗口，均不作为方案。）

| 目标应用名单 | 内置 13 个视频 App | 任意应用（含自定义包名） | 首页"添加应用"（内置常用 / 手机已安装两页） |

### 后台保活与电池优化

- **双服务互保**：前台服务（`START_STICKY`）常驻通知，每 60s 自检无障碍是否被系统停用（国产 ROM 常静默关闭），异常时通知引导重开；无障碍服务连接时反过来拉起前台服务
- **开机自启**：`BOOT_COMPLETED` 重启链路（无障碍启用状态重启后由系统保留）
- **省电策略对抗**：引导用户加入电池优化白名单 + 国产 ROM 的"自启动/后台运行"白名单；`startForegroundService` + 低重要性常驻通知是 Android 8+ 后台存活的最优合规形态
- **无银弹声明**：被用户手动强杀（force stop）或激进省电模式（如 MIUI 神隐）杀掉的服务，系统规定不允许自启，只能通知提醒

### 隐私与电量

- 无障碍服务**不读取屏幕内容**（`canRetrieveWindowContent=false`），仅接收包名与事件类型
- 加速度数据只在本机内存中计算，**不存储、不上传**
- 定位（仅开启驾驶检测时）：只读本机最后已知定位的速度字段，**不主动请求定位、不存储、不上传**
- 联网：**仅**在你手动点「检查更新」/下载更新时访问你配置的 GitHub 仓库，平时零联网、无任何数据上传
- 全部配置仅存于本机 SharedPreferences；无任何账号体系
- 电量消耗：传感器 2.5Hz 节流采样 + 15s 周期评估（无事件时基本休眠），实测级别 < 1%/天；常驻通知为低重要性，不弹横幅不震动（驾驶/更新提醒除外，均可关）

   - 手动暂停卡片：暂停 15 分钟 ~ 8 小时，或随时恢复

## 常见问题

**为什么没有关闭应用/息屏？** 按顺序检查：
- 无障碍服务、设备管理员是否已开启（App 首页有状态显示）
- 前台应用是否在目标列表中
- 是否在设定时间段内、是否被手动暂停
- 屏幕刚解锁是否不足 1 分钟
- 部分国产 ROM（MIUI/EMUI/ColorOS 等）会限制后台无障碍服务，需要在系统设置中允许自启动/后台运行，并将 App 加入电池优化白名单

**关闭视频 App 为什么没有完全杀掉？** 第三方应用无法结束其他应用的**前台**进程，必须先锁屏/回桌面后才能杀后台进程。若目标 App 有音乐播放器等前台服务，系统可能立即将其重新拉起——这是 Android 进程管理机制，可开启"强力暂停模式"彻底冻结（解锁后自动恢复）。

**强力暂停后应用打不开了？** 正常现象——该模式冻结了应用全部组件。点亮屏幕解锁后会自动恢复；若未恢复，重启手机也可解除。注意：该模式需要设备所有者权限，普通手机上会显示为不可用（关闭状态），不影响其他功能。

**睡觉时手机放在胸口，呼吸导致轻微晃动**：呼吸级规律微动已被识别为"疑似睡眠"信号，不阻止触发，仅要求 1.5 倍无操作时间。若仍不触发，可关闭「运动检测」或调低无操作时长。

**误触发了怎么办**：调大无操作时长，或开启「运动检测」（明显运动会阻止触发），或睡前用暂停卡片/磁贴暂停。倒计时期间甩动/偏转手机 1.5 秒以上也可自动取消。

**开车时会被触发吗**：开启「驾驶模式检测」后，GPS 速度 ≥25km/h 会弹通知让你选「驾驶模式」（暂停 10 分钟并自动复查）或「我是乘客」。没开导航（无 GPS 样本）时以 WiFi↔蜂窝网络切换作为行驶信号。

**醒着看长视频（完全不碰手机）会被锁吗**：若手机完全静止且无任何操作，任何传感器都无法区分"清醒"与"睡着"——这是物理限制。缓解方式：调大无操作时长（如 15~30 分钟）、设置时间段（只在深夜生效）、或手动暂停。

**隐私**：无障碍服务不读取屏幕内容（`canRetrieveWindowContent=false`），仅获取前台包名与事件类型；加速度数据只在本机内存中计算，不联网、不存储。应用无网络权限。

## 局限

- iOS 无法实现（系统限制第三方应用锁屏与读取前台应用），此方案仅适用于 Android
- 无法结束目标应用的前台进程（系统签名权限限制），关闭依赖"回桌面 + 锁屏 + 杀后台"的组合路径
- 小米、华为等系统自带的「专注模式/睡眠模式」也可替代部分场景，但无法做到「检测到你睡着」这种精细触发
